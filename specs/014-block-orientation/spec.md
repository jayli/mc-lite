# Feature Specification: Block Orientation System

**Feature Branch**: `014-block-orientation`
**Created**: 2026-02-22
**Status**: Draft
**Input**: User description: "给每个方块增加水平面的朝向的方向，即前后左后的属性，当消除一个方块（比如handrailA）的时候，下次再放置同样的方块（即handrailA）时，方向顺时针旋转90度，也就是说，假设消除一个面朝东的方块时，再次放置这个方块，则这个方块面朝南，当消除这个面朝南的方块时，再放置这个方块时则面朝西，当消除这个面朝西的方块时，再放置这个方块时则面朝北，依次类推。所有可被放置的方块都支持这个东南西北朝向的属性。请注意，这只是一个功能性的新增，方块的朝向不应当影响性能，包括不影响 face calling 和 instancedMesh 以及 后台合并等操作，这些性能相关的动作跟新增的朝向不应当互相影响，而要很好的兼容。需要澄清的是，新的实现需要对旧的indexedDB的存档做兼容，要能读取旧的存档。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 方块朝向记忆与旋转放置 (Priority: P1)

玩家在游戏中移除一个有方向性的方块（如 handrailA 栏杆），再次放置该类型方块时，方块的朝向会自动顺时针旋转 90 度。这为玩家提供了一种便捷的方式来调整方块方向，无需额外的 UI 操作。

**Why this priority**: 这是核心功能，直接影响玩家的游戏体验和建造效率。没有这个功能，整个特性无法交付价值。

**Independent Test**: 可以通过移除一个栏杆方块并再次放置，观察新方块的朝向来独立测试此功能。

**Acceptance Scenarios**:

1. **Given** 玩家背包中有 handrailA 方块且上次移除的该类型方块朝向东，**When** 玩家放置 handrailA 方块，**Then** 新放置的方块朝向南
2. **Given** 玩家背包中有 handrailA 方块且上次移除的该类型方块朝向南，**When** 玩家放置 handrailA 方块，**Then** 新放置的方块朝向西
3. **Given** 玩家背包中有 handrailA 方块且上次移除的该类型方块朝向西，**When** 玩家放置 handrailA 方块，**Then** 新放置的方块朝向北
4. **Given** 玩家背包中有 handrailA 方块且上次移除的该类型方块朝向北，**When** 玩家放置 handrailA 方块，**Then** 新放置的方块朝向东

---

### User Story 2 - 方块朝向持久化存储 (Priority: P2)

方块的朝向信息被正确保存到游戏存档中，玩家重新加载游戏后，方块的朝向状态与保存时一致。

**Why this priority**: 确保玩家的建造成果不会因游戏重启而丢失方向信息，这是完整用户体验的必要部分。

**Independent Test**: 放置一个有朝向的方块，保存游戏，重新加载，验证方块朝向是否正确还原。

**Acceptance Scenarios**:

1. **Given** 世界中存在朝向东的 handrailA 方块，**When** 玩家保存并重新加载游戏，**Then** handrailA 方块仍朝向东
2. **Given** 世界中存在朝向西的 handrailB 方块，**When** 玩家保存并重新加载游戏，**Then** handrailB 方块仍朝向西

---

### User Story 3 - 旧存档兼容 (Priority: P2)

对于旧版本存档中没有朝向信息的方块，系统能够正确加载并赋予默认朝向（东），保证游戏的向后兼容性。

**Why this priority**: 确保现有玩家不会因为升级而丢失存档，是产品升级的基本要求。

**Independent Test**: 加载一个旧版本存档，验证所有方块能正确显示且默认朝东。

**Acceptance Scenarios**:

1. **Given** 一个旧版本存档（方块数据为字符串类型），**When** 玩家加载该存档，**Then** 所有方块正常显示，朝向默认为东
2. **Given** 玩家在兼容模式下修改了旧存档的方块，**When** 玩家保存游戏，**Then** 新存档包含完整的朝向信息

---

### User Story 4 - 性能不受影响 (Priority: P3)

新增朝向功能后，游戏的渲染性能（帧率）、面剔除效率、InstancedMesh 合并效率与之前保持一致。

**Why this priority**: 性能是游戏体验的基础，但不能影响核心功能的交付。作为非功能性需求，需要在功能实现后验证。

**Independent Test**: 在放置大量有朝向的方块后，使用性能监控工具（按 P 键）对比帧率和渲染时间。

**Acceptance Scenarios**:

1. **Given** 游戏场景中有 1000 个带朝向的方块，**When** 玩家移动视角，**Then** 帧率不低于 60 FPS
2. **Given** 玩家快速放置和移除方块，**When** 触发后台合并，**Then** 合并过程无明显卡顿

---

### Edge Cases

- 玩家第一次放置某类型方块时（无移除历史），朝向默认为东
- 玩家移除方块后切换到其他类型方块再切换回来，朝向记忆保留，按方块类型独立记忆
- 方块被爆炸移除（TNT）时，同样记住朝向，与玩家移除行为一致
- 对称方块（如正方体）朝向变化在视觉上无差异，但仍存储朝向属性以保持一致性
- 重新加载游戏后，放置记忆重置，新放置的方块默认朝东；已存档方块的朝向保持不变

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须为每个放置在世界中的方块存储朝向属性，可选值为东(EAST)、南(SOUTH)、西(WEST)、北(NORTH)
- **FR-002**: 系统必须在玩家移除方块时，记录该方块的类型和朝向到内存中（仅当前游戏会话有效）
- **FR-003**: 系统必须在玩家放置方块时，根据记录的朝向计算新朝向（顺时针旋转 90 度）并应用
- **FR-004**: 系统必须支持所有可放置方块类型的朝向属性，包括但不限于 handrail、handrailA、handrailB、pillar 等
- **FR-005**: 系统必须在渲染方块时，根据朝向属性旋转方块的几何体
- **FR-006**: 系统必须将方块的朝向信息持久化到 IndexedDB 存档中
- **FR-007**: 系统必须能够正确读取旧版本存档（方块数据为字符串类型），并为缺少朝向信息的方块赋予默认朝向（东）
- **FR-008**: 朝向属性的存储格式必须兼容现有的数据结构，支持 `{ type: string, orientation?: number }` 格式
- **FR-009**: 方块朝向的渲染旋转必须在 InstancedMesh 层面实现，通过矩阵变换完成
- **FR-010**: 方块朝向不应影响 Face Culling 系统的正确性
- **FR-011**: 方块朝向不应影响后台合并（Consolidation）系统的正确性

### Key Entities

- **BlockOrientation**: 方块朝向枚举，值为 EAST(0)、SOUTH(1)、WEST(2)、NORTH(3)，代表方块在水平面上的四个方向
- **BlockData**: 方块数据结构，扩展为支持 `{ type: string, orientation: number }` 格式，其中 `orientation` 为可选字段，默认为 0（东）
- **PlacementMemory**: 放置记忆，存储每种方块类型上次移除时的朝向，仅当前游戏会话有效，用于计算下次放置时的朝向

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 玩家可以在 3 次操作内（移除-放置-验证）确认方块朝向正确旋转 90 度
- **SC-002**: 加载旧版本存档时，所有方块正常显示且无报错
- **SC-003**: 在包含 1000 个带朝向方块的场景中，帧率保持在 55 FPS 以上
- **SC-004**: 保存并重新加载游戏后，方块朝向 100% 正确还原
- **SC-005**: Face Culling 系统在带朝向方块场景中工作正常，无视觉异常

## Clarifications

### Session 2026-02-22

- Q: 放置记忆是否应该在游戏会话之间持久化保存？ → A: 不持久化 - 放置记忆仅在当前游戏会话有效，重新加载游戏后新放置的方块默认朝东；但已存档方块的朝向信息需要保持

## Assumptions

1. **默认朝向**：旧存档和新放置的方块（无移除历史或重新加载游戏后）默认朝向东（EAST, orientation=0）
2. **朝向记忆范围**：放置记忆仅在当前游戏会话有效，不跨会话持久化，按方块类型独立存储
3. **几何体旋转**：方块几何体绕 Y 轴旋转实现朝向变化，东为 0 度，南为 90 度，西为 180 度，北为 270 度
4. **数据兼容**：旧存档中方块数据为字符串类型，新存档为对象类型 `{ type, orientation }`，系统同时支持两种格式
5. **性能影响**：朝向通过矩阵旋转实现，对 InstancedMesh 的性能影响可忽略不计
6. **对称方块**：对于几何对称的方块（如正方体），朝向变化在视觉上无差异，但仍存储朝向属性以保持一致性
