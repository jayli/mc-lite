# Feature Specification: 丧尸敌人系统

**Feature Branch**: `001-zombie-enemy`
**Created**: 2026-02-11
**Status**: Draft
**Input**: User description: "我要为游戏添加丧尸，丧尸看见玩家后会移动向玩家，丧尸不会跳，只会上下一级台阶，丧尸是一个方块尺寸的长宽，两个方块高度。请按照我的世界原版游戏人物的风格和样貌，生成丧尸，丧尸的实现代码放在 src/enemy/Zombie.js 中，跟玩家一样，丧尸跟世界有碰撞效果，不能穿模，丧尸可以被枪消灭。请你尽可能内聚的实现丧尸的功能，不要对已有的其他功能做改动。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 丧尸生成与渲染 (Priority: P1)

玩家在游戏中能够看到按照我的世界原版风格设计的丧尸实体。丧尸具有方块化的外观，符合游戏的整体视觉风格。丧尸以正确的尺寸（1个方块宽度，1个方块长度，2个方块高度）显示在游戏中。

**Why this priority**: 这是最基础的功能，没有丧尸的可视化表示，后续的所有行为都无法体现。

**Independent Test**: 可以在特定位置生成丧尸，并验证其外观、尺寸和渲染是否符合预期，独立展示丧尸的基本视觉效果。

**Acceptance Scenarios**:

1. **Given** 游戏运行中且丧尸模块已加载, **When** 在指定坐标生成丧尸, **Then** 丧尸按照我的世界原版风格正确渲染，尺寸为1x1x2方块单位
2. **Given** 丧尸已经生成, **When** 玩家接近丧尸, **Then** 丧尸可见并与游戏环境融合

---

### User Story 2 - 丧尸AI与追踪 (Priority: P1)

当丧尸检测到玩家在其视野范围内时，会自动朝玩家方向移动。丧尸具备基本的路径寻找能力，能够跟随玩家的移动。

**Why this priority**: 这是丧尸的核心互动机制，让丧尸真正成为游戏中的威胁元素。

**Independent Test**: 将玩家放置在丧尸附近，验证丧尸是否会检测到玩家并开始移动追逐。

**Acceptance Scenarios**:

1. **Given** 丧尸未发现玩家, **When** 玩家进入丧尸感知范围, **Then** 丧尸开始朝玩家方向移动
2. **Given** 玩家在丧尸感知范围内, **When** 玩家改变位置, **Then** 丧尸调整移动方向以持续追踪玩家
3. **Given** 玩家离开丧尸感知范围, **When** 玩家移动超出感知距离, **Then** 丧尸停止追踪并可能回到初始状态

---

### User Story 3 - 丧尸物理与碰撞 (Priority: P1)

丧尸具备真实的物理特性，与世界进行正确的碰撞检测，不能穿越墙壁或其他障碍物。丧尸可以正常上下一级台阶但无法跳跃。

**Why this priority**: 物理和碰撞系统确保丧尸行为的真实性和可预测性，避免穿模等不真实现象。

**Independent Test**: 测试丧尸与各种方块类型的碰撞、上下台阶的能力以及无法跳跃的限制。

**Acceptance Scenarios**:

1. **Given** 丧尸向前移动遇到墙体, **When** 丧尸碰到不可穿透方块, **Then** 丧尸停止移动并被阻挡
2. **Given** 丧尸前方有一级台阶高度差, **When** 丧尸移动到台阶前, **Then** 丧尸能够上升或下降一级台阶
3. **Given** 丧尸前方有多级台阶或悬崖, **When** 丧尸试图移动过去, **Then** 丧尸无法跳跃越过超过一级台阶的高度差
4. **Given** 玩家与丧尸在同一空间, **When** 两者发生碰撞, **Then** 双方都会受到相应的碰撞物理影响

---

### User Story 4 - 丧尸战斗与消灭 (Priority: P2)

玩家可以使用枪械对丧尸造成伤害，当丧尸生命值降至零时，丧尸被消灭并从游戏中移除。

**Why this priority**: 这是玩家与丧尸互动的重要组成部分，提供游戏战斗体验。

**Independent Test**: 玩家使用枪械攻击丧尸直到其被消灭，验证整个战斗流程。

**Acceptance Scenarios**:

1. **Given** 玩家持有枪械且瞄准丧尸, **When** 玩家开火击中丧尸, **Then** 丧尸受到相应伤害并减少生命值
2. **Given** 丧尸生命值大于零, **When** 受到致命伤害使生命值降至零或以下, **Then** 丧尸被消灭并从游戏中移除
3. **Given** 玩家攻击丧尸, **When** 攻击命中丧尸, **Then** 应该有适当的视觉/音频反馈表明伤害发生

---

### User Story 5 - 丧尸生命周期管理 (Priority: P2)

丧尸系统具备完整的生命周期管理，包括生成、更新和清理，确保性能不受过多实体影响。

**Why this priority**: 系统稳定性与性能优化的关键要素。

**Independent Test**: 验证大量丧尸同时存在时的性能表现和内存管理。

**Acceptance Scenarios**:

1. **Given** 游戏中有多个丧尸实体, **When** 进入特定区域时, **Then** 合理数量的丧尸被激活和管理
2. **Given** 丧尸超出活跃区域, **When** 达到特定距离或条件时, **Then** 丧尸被适当移除以节省资源

---

### Edge Cases

- 当丧尸处于无法到达玩家的位置（如完全被封闭的空间）时，如何处理？
- 如果多个丧尸同时追踪同一个玩家会发生什么？
- 当丧尸正在追踪玩家但玩家突然消失（例如瞬移或传送）时如何响应？
- 在世界边界或特殊地形处丧尸的行为如何？
- 当丧尸和玩家处于相同坐标时碰撞处理如何？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供丧尸实体的视觉表示，符合我的世界原版角色风格
- **FR-002**: 系统 MUST 实现丧尸的基本AI逻辑，使其能够感知并追踪玩家
- **FR-003**: 系统 MUST 确保丧尸具有正确的物理特性，包括与世界的碰撞检测
- **FR-004**: 系统 MUST 允许丧尸上下一级台阶但禁止跳跃动作
- **FR-005**: 系统 MUST 实现丧尸的生命值系统和被枪械消灭的功能
- **FR-006**: 系统 MUST 将丧尸的实现代码放置在 `src/enemy/Zombie.js` 文件中
- **FR-007**: 系统 MUST 确保丧尸尺寸为1个方块宽度、1个方块长度、2个方块高度
- **FR-008**: 系统 MUST 实现丧尸与玩家之间的碰撞检测，防止穿模
- **FR-009**: 系统 MUST 确保丧尸不会对现有其他功能进行不必要的修改
- **FR-010**: 系统 MUST 实现丧尸的感知范围检测，当玩家在此范围内时激活追踪行为

### Key Entities

- **Zombie**: 表示丧尸实体，包含位置、旋转、生命值、状态（idle、chasing、dead）、AI参数等属性
- **ZombieManager**: 管理游戏中所有丧尸实例的创建、更新和销毁
- **ZombieBehavior**: 控制丧尸AI逻辑，包括追踪、移动、碰撞响应等行为

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 丧尸能够正确渲染并显示在我的世界风格视觉环境中，尺寸精度达到1个像素级别
- **SC-002**: 丧尸能够成功追踪玩家且移动平滑，在标准硬件配置下帧率保持在30fps以上
- **SC-003**: 丧尸与世界碰撞检测准确率达到99%以上，无明显穿模现象
- **SC-004**: 玩家能够在平均5次射击以内成功消灭一个丧尸
- **SC-005**: 丧尸能够正确识别并响应10米范围内的玩家存在
- **SC-006**: 系统在管理最多10个活跃丧尸时，CPU使用率不超过15%
