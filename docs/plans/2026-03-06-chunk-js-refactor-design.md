# Chunk.js 分拆重构设计文档

## 背景
Chunk.js 目前已超过 1700 行，代码臃肿，职责不清晰，不利于维护和扩展。

## 分拆方案
采用按功能职责分拆方案，将 Chunk.js 拆分为5个职责清晰的文件：

### 1. Chunk.js (核心模块)
- **行数：约350行**
- **职责：**
  - 构造函数和属性定义
  - 核心生命周期管理
  - 公共API入口
  - 子模块调度和协调
  - 状态管理

### 2. ChunkConsolidation.js (合并模块)
- **行数：约300行**
- **职责：**
  - scheduleConsolidation() 方法
  - consolidate() 方法
  - 方块合并相关的所有辅助逻辑
  - 脏方块管理

### 3. ChunkGenerator.js (生成模块)
- **行数：约350行**
- **职责：**
  - gen() 方法
  - 地形生成逻辑
  - 实体（树、结构等）生成
  - 区块初始化逻辑

### 4. ChunkPersistence.js (持久化模块)
- **行数：约250行**
- **职责：**
  - saveDebounced() 方法
  - _saveChestStates() 方法
  - 区块数据持久化
  - 数据加载逻辑

### 5. ChunkRenderUtils.js (渲染工具模块)
- **行数：约550行**
- **职责：**
  - 面剔除更新逻辑
  - AO计算和更新
  - 碰撞体生成
  - dispose() 方法
  - 其他渲染相关工具方法

## 实施原则
1. **完全兼容：** 保持原有功能和对外API完全不变，只做代码移动，不修改业务逻辑
2. **最小改动：** 尽可能减少对现有代码的侵入性修改
3. **逐步验证：** 每一步分拆后都进行功能验证，确保不引入新的Bug
4. **保留结构：** 所有方法仍然挂载在Chunk类原型上，外部调用方式不变

## 后续计划
分拆完成后，可以考虑进一步优化：
- 将通用工具方法提取到更上层的utils目录
- 为每个子模块添加单元测试
- 优化子模块之间的依赖关系
