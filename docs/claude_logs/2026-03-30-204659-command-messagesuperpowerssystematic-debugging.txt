⏺ Phase 1 完成：根本原因已识别

  问题根源

  我找到了问题的根本原因：

  1. AO 数据基于世界坐标计算：AO_NEIGHBOR_OFFSETS 数组按固定的世界方向顺序（+X,
  -X, +Y, -Y, +Z, -Z）计算每个面的 AO 值，然后打包成 aoLow 和 aoHigh
  2. Shader 使用固定的顶点 ID 解包 AO：
    - 顶点 ID 0-3 → +X 面的 4 个角落
    - 顶点 ID 4-7 → -X 面
    - 顶点 ID 8-11 → +Y 面
    - 顶点 ID 12-15 → -Y 面
    - 顶点 ID 16-19 → +Z 面
    - 顶点 ID 20-23 → -Z 面
  3. 方块旋转只改变变换矩阵：当方块旋转时，setMatrixAt
  设置了旋转矩阵，几何体顶点跟着旋转，但顶点 ID 不变
  4. 结果：旋转 90° 后，原来 +X 方向的几何面现在朝向 +Z，但 Shader 仍用顶点 ID
  0-3 从 AO 数据中取出 +X 方向的 AO 值，导致 AO 阴影"跟着旋转"

⏺ Phase 2: 模式分析

  现在我完全理解了问题。让我设计解决方案。

  问题本质

  1. Shader 的 AO 读取逻辑：
    - 顶点 ID → 面索引 → 固定的世界方向 AO 值
    - 顶点 0-3 始终读取 +X 面的 AO，顶点 16-19 始终读取 +Z 面的 AO
  2. 旋转的影响：
    - 方块旋转 90°（orientation=1，朝南）后
    - 原本的 +X 几何面现在朝向 +Z（世界南）
    - 但 Shader 仍用顶点 ID 0-3 读取 +X 面的 AO 值
    - 这导致 AO 阴影"跟着旋转"

  解决方案

  在 Shader 中根据方块朝向重新映射 AO 面索引：

  当方块旋转时，需要根据 orientation 值重新映射：
  - orientation=0（朝东）：无变化
  - orientation=1（朝南/旋转90°）：+X→+Z, +Z→-X, -X→-Z, -Z→+X
  - orientation=2（朝西/旋转180°）：+X→-X, +X→+X, +Z→-Z, -Z→+Z
  - orientation=3（朝北/旋转270°）：+X→-Z, -Z→-X, -X→+Z, +Z→+X

  这需要：
  1. 添加 aOrientation 实例属性传递方块朝向
  2. 修改 Shader 中的 getAo 函数，根据 orientation 重映射面索引

  修复总结

  问题根本原因

  当方块旋转时，几何体的面朝向改变，但 AO 数据是按世界坐标存储的。原来的 shader
  直接用顶点 ID 读取 AO，没有考虑方块旋转，导致 AO 阴影"跟着旋转"。

  解决方案

  在数据层面解决问题：在存储 AO 数据时根据方块朝向重排顶点 ID，使得 shader
  可以按原来的方式读取，不需要知道方块是否旋转。
