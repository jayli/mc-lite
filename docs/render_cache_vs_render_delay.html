核心差异

帧分散方案

  • 不改变数据结构，无持久化风险
  • 改动集中在调度层（2-3 个文件）
  • 一个 feature flag 即可回退
  • 每帧工作量可控、可观测
  • 参数可调：每帧 chunk 数、间隔帧数

renderCache 方案

  • 需要改 9+ 文件，涉及读写链路保真
  • 影响 IndexedDB schema
  • contentRevision 单调性约束
  • overflow 污染处理复杂
  • bug 面大，已多次失败
